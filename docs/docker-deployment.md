# Docker Deployment Guide

Deploy Server Monitor on your own server using Docker Compose. The entire setup is automated with a single installation script.

## Prerequisites

- **Docker** (v20+) — [Install Docker](https://docs.docker.com/get-docker/)
- **Docker Compose** v2 — [Install Compose](https://docs.docker.com/compose/install/)
- **For Domain Mode:** Nginx and Certbot
  ```bash
  sudo apt-get install nginx certbot python3-certbot-nginx
  ```

## Quick Start (One Command)

```bash
# Download and run installer
curl -fsSL https://raw.githubusercontent.com/tuyencaovn/saasguard.tech/master/install.sh | bash
```

### Clean reinstall (`--force`)

To wipe an existing deployment (containers, database volume, and `.env`) and
install fresh from scratch:

```bash
bash install.sh --force      # or: --reset
```

⚠️ This deletes all data. The installer also detects other Nginx sites already
serving your domain and offers to disable them (old/manual configs cause
wrong routing when two server blocks share one `server_name`).

The script will:
1. Check prerequisites
2. Download `docker-compose.prod.yml` and `.env.example` if missing (self-contained)
3. Create `.env` and auto-generate secrets (database password, JWT secret, admin password)
4. Interactively ask for your admin email and domain/IP, then write them to `.env`
5. Detect deployment mode (domain or IP) and auto-assign free host ports
6. Setup Nginx + SSL (if domain mode)
7. Pull Docker images from GitHub Container Registry
8. Start all services with `docker compose up -d`
9. Display your access URL and the generated admin password

## Manual Installation (Step by Step)

### 1. Download Files

```bash
# Create project directory
mkdir -p ~/server-monitor
cd ~/server-monitor

# Download compose and config
wget https://raw.githubusercontent.com/tuyencaovn/saasguard.tech/master/docker-compose.prod.yml
wget https://raw.githubusercontent.com/tuyencaovn/saasguard.tech/master/.env.example
```

### 2. Configure Environment

```bash
# Copy example to actual config
cp .env.example .env

# Edit with your values
nano .env
```

**You only need to set two variables:**
- `ADMIN_EMAIL` — Your admin email (used for login and SSL registration)
- `FRONTEND_URL` — Access URL (e.g., `https://monitor.example.com` or `http://192.168.1.100:3006`)

**Auto-generated by `install.sh`** (leave as `CHANGE_ME`):
- `DATABASE_PASSWORD` — Random 32-char password
- `JWT_SECRET` — Random 48-char secret
- `ADMIN_PASSWORD` — Random 20-char password (printed at the end of install)

**Auto-assigned** (leave as `auto`):
- `API_PORT`, `DASH_PORT` — First free host ports (internal behind Nginx)

**Optional:**
- `SMTP_*` — Email notifications
- `TELEGRAM_BOT_TOKEN` — Telegram alerts
- `BIND_HOST` — Default `127.0.0.1` (use with Nginx), or `0.0.0.0` for direct IP access

> If you set `DATABASE_PASSWORD`, `JWT_SECRET`, or `ADMIN_PASSWORD` to your own
> value instead of `CHANGE_ME`, the installer keeps your value untouched.

### 3. Setup Nginx (Domain Mode Only)

If `FRONTEND_URL` starts with a domain:

```bash
# Create Nginx config
sudo tee /etc/nginx/sites-available/saasguard > /dev/null <<'EOF'
server {
    listen 80;
    server_name monitor.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:3005/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /socket.io/ {
        proxy_pass http://127.0.0.1:3005/socket.io/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3006;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
EOF

# Enable and test
sudo ln -s /etc/nginx/sites-available/saasguard /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 4. Setup SSL (Domain Mode)

```bash
# Get certificate from Let's Encrypt
sudo certbot --nginx -d monitor.example.com --non-interactive --agree-tos -m admin@example.com

# Auto-renewal is configured by certbot
```

### 5. Start Services

```bash
# Pull latest images from GitHub
docker compose -f docker-compose.prod.yml pull

# Start in background
docker compose -f docker-compose.prod.yml up -d

# Check status
docker compose -f docker-compose.prod.yml ps

# View logs
docker compose -f docker-compose.prod.yml logs -f
```

### 6. Verify Installation

```bash
# Check backend health
curl http://localhost:3005/health

# Check frontend (IP mode)
curl http://localhost:3006/login

# Check frontend (domain mode via Nginx)
curl https://monitor.example.com/login
```

## Configuration Options

### Deployment Modes

#### Domain Mode (Recommended)
```env
FRONTEND_URL=https://monitor.example.com
BIND_HOST=127.0.0.1
```
- Nginx reverse proxy routes all traffic
- SSL via Let's Encrypt (auto-renewed)
- Single domain endpoint

#### IP Mode
```env
FRONTEND_URL=http://192.168.1.100:3006
BIND_HOST=0.0.0.0
```
- Direct access via IP address
- No Nginx required
- Frontend and backend exposed separately (port 3005, 3006)

### Email Notifications

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASSWORD=app-password
SMTP_FROM=alerts@saasguard.io
```

### Telegram Notifications

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-1234567890
```

**Create a bot:** chat with `@BotFather` → `/newbot` → copy the token.

**Find your chat ID:**
- Personal chat (simplest, no group needed): message `@userinfobot` → it replies `Id: 123456789` (a positive number).
- Or message your own bot once, then:
  ```bash
  curl -s "https://api.telegram.org/bot<BOT_TOKEN>/getUpdates"
  ```
  Read `chat.id` from the response. If it returns `{"result":[]}`, you haven't
  messaged the bot yet, or a webhook is set — clear it with
  `curl -s "https://api.telegram.org/bot<BOT_TOKEN>/deleteWebhook"` then message again.
- Group chat (whole team): add the bot to the group, send a message, then read the
  **negative** `chat.id` (e.g. `-1001234567890`).

### PM2 Process Monitoring

To monitor PM2 processes running on the host, the backend connects to the host's
PM2 daemon.

**`PM2_HOME` is auto-detected.** `install.sh` reads the path straight from the
running PM2 daemon process and writes it to `.env` before starting — so a fresh
install needs no manual PM2 config, as long as PM2 is already running.

Two things to know:

1. **PM2 must be running at install time** for auto-detect to work. If you start
   PM2 later, set `PM2_HOME` manually (the `.pm2` dir of the user running PM2,
   e.g. `/home/devops/.pm2`) and recreate the backend:
   ```bash
   docker compose -f docker-compose.prod.yml up -d --force-recreate backend
   ```

2. **PM2 major version must match.** The backend image ships pm2 7.x. Check the
   host with `pm2 --version`; if it differs by a major version, the in-container
   client spawns its own empty daemon instead of attaching to the host one.

## Common Operations

### View Logs
```bash
docker compose -f docker-compose.prod.yml logs -f
docker compose -f docker-compose.prod.yml logs -f backend  # Just backend
docker compose -f docker-compose.prod.yml logs -f frontend # Just frontend
```

### Stop Services
```bash
docker compose -f docker-compose.prod.yml down
```

### Restart Services
```bash
docker compose -f docker-compose.prod.yml restart
```

### Restart Specific Service
```bash
docker compose -f docker-compose.prod.yml restart backend
docker compose -f docker-compose.prod.yml restart frontend
```

### Update to Latest Images
```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d
```

### Database Backup
```bash
# Backup PostgreSQL
docker compose -f docker-compose.prod.yml exec db pg_dump -U server-monitor server-monitor > backup.sql

# Restore from backup
docker compose -f docker-compose.prod.yml exec -T db psql -U server-monitor server-monitor < backup.sql
```

### Resize Container Memory Limits
Edit `docker-compose.prod.yml` and add resource limits:
```yaml
services:
  backend:
    deploy:
      resources:
        limits:
          memory: 1G
        reservations:
          memory: 512M
```

## Troubleshooting

### Images won't pull
```bash
# Check GitHub Container Registry login
echo $GITHUB_TOKEN | docker login ghcr.io -u USERNAME --password-stdin

# Or pull manually
docker pull ghcr.io/tuyencaovn/saasguard.tech/backend:latest
docker pull ghcr.io/tuyencaovn/saasguard.tech/frontend:latest
```

### Port already in use
```bash
# Change ports in .env
API_PORT=3007
DASH_PORT=3008

# And update Nginx config if applicable
```

### Database connection failed
```bash
# Check database is healthy
docker compose -f docker-compose.prod.yml exec db pg_isready -U server-monitor

# Reset database
docker compose -f docker-compose.prod.yml down -v  # Warning: deletes data!
```

### Nginx 502 Bad Gateway
- Backend may still be starting, wait 30 seconds
- Check backend logs: `docker compose -f docker-compose.prod.yml logs backend`
- Verify `BIND_HOST=127.0.0.1` in .env (not 0.0.0.0)

### Backend stays "unhealthy"
- The app listens on port 3005 inside the container; the compose file sets
  `PORT=3005` for the backend. If you overrode it, the healthcheck (which probes
  `localhost:3005/health`) will fail.

### PM2 shows "No processes found"
- `install.sh` auto-detects `PM2_HOME`, but only if PM2 was running at install
  time. Check the value in `.env` — it must be the `.pm2` dir of the user running
  PM2 (e.g. `/home/devops/.pm2`, not `/root/.pm2`). Fix it and recreate backend.
- Host `pm2 --version` must match the backend's pm2 major version (7.x).
- After editing `PM2_HOME`, recreate the backend (mounts only change on recreate):
  ```bash
  docker compose -f docker-compose.prod.yml up -d --force-recreate backend
  ```
- Verify the mount points source and destination at the same path:
  ```bash
  docker inspect server-monitor_backend --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
  ```

## Upgrade Guide

When a new version is released:

```bash
# Pull latest images
docker compose -f docker-compose.prod.yml pull

# Restart services
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d

# Check health
docker compose -f docker-compose.prod.yml logs frontend
```

Database schema migrations run automatically on startup.

### Pinning a Specific Version

Images are published with semantic version tags on every `vX.Y.Z` git tag:

```
ghcr.io/tuyencaovn/saasguard.tech/backend:1.0.0   # exact version
ghcr.io/tuyencaovn/saasguard.tech/backend:1.0     # latest 1.0.x patch
ghcr.io/tuyencaovn/saasguard.tech/backend:1       # latest 1.x release
ghcr.io/tuyencaovn/saasguard.tech/backend:latest  # newest build on master
```

`docker-compose.prod.yml` uses `:latest` by default. To pin a stable version,
edit the `image:` lines:

```yaml
services:
  backend:
    image: ghcr.io/tuyencaovn/saasguard.tech/backend:1.0
  frontend:
    image: ghcr.io/tuyencaovn/saasguard.tech/frontend:1.0
```

## Security Recommendations

1. **Secrets are auto-generated** by `install.sh` (database password, JWT secret,
   admin password) — no manual action needed. Save the admin password shown at the
   end of install; it is stored only in your `.env`.

2. **Use HTTPS in production** (domain mode with Certbot)

3. **Keep Docker updated**
   ```bash
   docker --version  # Should be v20+
   ```

4. **Limit resource usage** in `docker-compose.prod.yml`:
   ```yaml
   deploy:
     resources:
       limits:
         memory: 1G
   ```

5. **Regular backups**
   ```bash
   # Daily backup script
   0 2 * * * cd ~/server-monitor && docker compose -f docker-compose.prod.yml exec -T db pg_dump -U server-monitor server-monitor | gzip > backups/backup-$(date +\%Y\%m\%d).sql.gz
   ```
